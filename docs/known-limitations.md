# 已知限制

本文件记录 PDFX 初始版本与规格、M0 原型及原定验收范围之间仍然存在的差异，以及在本环境中未执行的人工验证。这里列出的项目都是有意保留的边界，不是待办清单；修复它们需要单独的设计与实现，不能靠文档更新解决。

## 工作区信息架构

- 生产工作区没有实现 M0 原型顶部的“注释/编辑”模式切换，也没有五个页签（注释、形状、插入、编辑文本、表单）。工具通过页面覆盖层与左右侧面板提供。
- `src/prototype/` 与 `prototype.html` 仍然是信息架构与文案的参考实现，不随生产工作区更新。

## 渲染与性能

- 查看器是单页模式：只按需渲染当前页，缩略图懒加载。规格中的多页渐进渲染（用户故事 7）没有实现。
- 打印准备严格按页串行，解码后的 RGBA 位图峰值固定为一页；但每页压缩后的 PNG Blob 会一直存活到打印结束、取消、切换文档或组件卸载。所选范围很大时，压缩 Blob 总量仍可能占用可观内存。真实桌面 WebView 的内存曲线未人工 profile。

## 界面与语言

- 设置中的英文选项只更新 `<html lang>`（以及主题/语言的应用状态），可见文案始终为简体中文；没有 i18n 资源文件。
- 应用级退出（`Cmd+Q` 或菜单“退出 PDFX”）不经过窗口关闭守卫，不会提示未保存修改。窗口关闭按钮与 `Cmd+W` 会显示中文确认。
- 关闭确认对话框打开时按 Escape 也会关闭设置面板：两者都在 window 级监听 keydown，属于既有的模态协作限制。
- 关闭确认打开期间，App 层会忽略菜单动作与文件拖放，但原生菜单项本身不会置灰。

## 字体

- 初始版本只随包内置 Noto Sans SC（CJK 回退）与 PDF base-14 字体。仅这套字体完成了 CIDFontType2 + FontFile2 子集管线与许可复核。
- ADR-0006 列出的 Noto Serif SC、Inter、Noto Serif 与 Liberation Sans/Serif 未打包，见 [ADR-0011](adr/0011-initial-shipped-fonts.md)。文档原字体仍会被优先复用；缺少字形时回退到内置字体并提示。

## 命令边界与架构

- 边界使用领域命令（`apply_text_edit`、`insert_image`、`create_text_markup_annotation`、`save_document` 等），而不是规格示意中的通用 `begin_session/apply_edit/undo/redo` 信封。Tauri 命令边界仍然只有一个，`src/lib/backend.ts` 是前端唯一入口。
- 页面内容、注释与链接共用统一编辑历史，但页面操作、表单结构编辑等各有自己的恢复动作类型；这是实现选择，不是待修复缺陷。
- 以下重构属于已接受的债务，留待后续专项处理：拆分 `App.tsx` 与 `save.rs`；合并四处原子写实现；统一目标路径/权限守卫；替换按字段种类展开的 `match`；引入共享的矩形类型。

## 图层

- 图层面板列出文档级 Optional Content Group（`/OCProperties /D /OCGs`），而不是只列当前页的图层。PDF 的 OCG 本身就是文档级对象。
- 隐藏图层的文字仍会出现在文本提取与文本层中，因为 PDFium 的文本提取器忽略 OCG 可见性；若在提取阶段过滤，会与使用活动文档映射字符索引的文本编辑目标错位，导致编辑命中错误对象。

## 链接

- 源文档页面内容中的图片可以选择并添加链接，但只识别页面顶层的图片对象（`PdfPageObjectType::Image`）。嵌套在 Form XObject 内部的图片不可选。
- 已插入的会话图片（`page_images` 返回的对象）由图片编辑覆盖层管理，不出现在源图片链接目标中，避免同一区域出现两套可点击热区。

## 附件

- 打开附件前会再显示一次中文确认。这是超出票 36 所述“仅删除需确认”的有意安全增强，不是规格要求的回退。

## 验证状态

- 以下人工验收未在本环境执行：真实阅读器（Preview、Adobe Acrobat Reader、Chrome）中的打开/编辑/保存/链接点击矩阵；Windows 实机安装、文件关联与打印；较旧 macOS（含 macOS 12 与 Intel 硬件）实机启动；操作系统文件关联注册/取消的端到端流程；原生菜单与快捷键的人工验收；真实打印机输出与 macOS 原生打印面板的 `afterprint` 行为；真实 2000 页文档在桌面 WebView 中的内存曲线；真实磁盘写满时的写入行为（自动化使用注入错误与只读目录模拟）。
- 自动化覆盖范围是命令边界、PDFium 适配层、lopdf 结构解析与 React 组件/原型交互，不等同于上述人工验收。
