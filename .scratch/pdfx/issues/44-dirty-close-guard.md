# 44: 未保存标记与关闭确认

**What to build:** 编辑器在 Document 有未保存修改时（任意文字、Text Box、Annotation 或页面操作之后）在标题栏显示未保存标记，并在关闭窗口时弹出“保存 / 不保存 / 取消”确认；保存后标记清除，撤销回到保存点时标记也清除。

**Blocked by:** 10 (Save As / Save Changes 管线)

**Status:** done

- [x] 任一编辑动作（编辑文字、新建/变换 Text Box、撤销/重做）后标题栏出现未保存标记。
- [x] 保存成功后标记与 `dirty` 状态清除；继续编辑后再次出现。
- [x] 关闭有未保存修改的窗口时显示中文确认，三个选项分别执行保存后关闭、直接关闭、取消关闭。
- [x] 无未保存修改时关闭不弹确认。
- [x] 关闭确认与标题标记只依赖命令边界返回的 dirty 状态，不在前端重复推断。

- **能力审计**：`Window.destroy()` 调用 `plugin:window|destroy`，需要 `core:window:allow-destroy`；已从生成的 desktop schema 核对 `core:default` 只包含 `core:window:default`，而该默认集不含 `destroy`（也不含 `close`），故显式权限确有必要。不选 `core:window:allow-close`：`close()` 会再次发出 `close-requested`，而守卫总是先 `preventDefault()`，无法用同一路径完成“已决定关闭”的收尾；`destroy()` 不重发事件，正好表达一次性销毁。权限仍只作用于既有 capability 的 `windows: ["main", "document-*"]`，未加通配窗口或其它 window 权限（`allow-set-title` 为既有）。`destroyWindow` 仅由 `closeWindow()` 在守卫判定后调用，未挂到 `window`、未暴露 IPC/事件入口；CSP 仍为 `default-src 'self'`，无远程内容或新网络/遥测能力，前端 bundle 无新增远端能力。
